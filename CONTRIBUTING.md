# Contributing

Thank you for helping improve DocxGen UI.

Before opening a change, search existing issues and discuss substantial product
or architecture changes in an issue. Keep pull requests focused and include
tests for behavior changes.

Base feature branches on `develop`, use an imperative commit subject, and run
the complete verification suite in `docs/development.md`. Pull requests should
explain the user-visible outcome, security/privacy impact, tests run, and any
platform that was not verified.

By participating, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
